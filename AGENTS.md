# Agent instructions for hyprland-canvas

A Hyprland user daemon that pans floating windows like an infinite desktop. It
is not a fork of Hyprland and shares no code with it: it speaks to the running
compositor over that compositor's IPC socket and Lua API. Python 3.12+, the
package is `canvas/`, `pyyaml` is the only runtime dependency, and `canvasd` and
`canvas-ctl` are its two entry points.

## Fast path

- Install: `uv sync --dev`
- Focused check: `uv run pytest tests/test_<area>.py`
- Full suite: `uv run pytest --cov=canvas --cov-fail-under=80` (CI adds
  `--cov-report=term-missing -v`)
- Lint/format: `uv run ruff check . && uv run ruff format --check .`
- Types: `uv run mypy canvas/`
- Markdown: `npx --yes markdownlint-cli2@0.23.3 $(git ls-files '*.md' | tr '\n' ' ')`

CI is the gate, and it runs the matrix 3.12 / 3.13 / 3.14 / 3.15. The Fast path
above is the same set on one interpreter, so it catches a failure before CI does
but does not cover the other three versions.

## Boundaries

- `CHANGELOG.md` has two halves: the bullet list is generated by
  `scripts/release-notes.sh` from commit subjects, so the subject is the entry
  and there is no second pass to polish it; the `### Details` block under a
  version heading is written by hand, at release time, for the entries whose
  subject is not enough.
- Release bodies are edited with `gh release edit`, after saving the current one
  with `gh release view <tag> --json body`.
- The version lives in three places: `canvas/__init__.py`, `pyproject.toml`, and
  that release's heading in `CHANGELOG.md`. The first is the fallback
  `canvasd --version` uses when the package is not installed as metadata, so
  missing it leaves the binary reporting the release before.
- Config defaults live in `DEFAULT_CONFIG` in `canvas/config.py`. The repo's
  `config.yml` is a copy template and is deliberately not shipped in the wheel.
- Runtime dependencies: one, `pyyaml`. Hyprland IPC is one short-lived Unix
  socket per request — the server closes after each response — so the pan loop
  pays a connect per frame instead of a subprocess per frame.

## Known traps

- `mypy` covers `canvas/` only. `tests/` is untyped and CI will not tell you.
- A new `CANVAS_DEBUG` trace event belongs in `docs/debugging.md`, which holds
  the complete level 1 and level 2 vocabulary.
- Toggle state is versioned and older files keep loading: v4 is current, and v2
  and v3 must still restore.
- The daemon targets Hyprland 0.55+ with a Lua config. Geometry calls changed
  between 0.55 and 0.56 and `hl.bind` options changed between 0.56 and 0.57
  (`mouse` is parsed now and is exclusive with `release`), and none of this is
  testable without a live compositor.
- `canvas.auto_float` windowrules are registered at toggle time, not at config
  load, so a missing `SPAWN_RULES_REGISTER` trace means `auto_float` is off or
  the toggle did not reach that code. The trace is re-sent once a second while
  canvas mode is on, so it marks the check, not a newly created rule.
